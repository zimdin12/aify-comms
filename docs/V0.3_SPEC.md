# v0.3 and beyond — specification

**Status:** DRAFT for review, rewritten after `comms-senior-dev` returned REWORK on the first
version. Three items, now in **three separate releases** rather than one.

## What the review changed

1. **The reconciler extraction does not share a release with the notification features.**
   *"Different failure modes, different rollback, different acceptance evidence. Mixing them would
   make any post-release send/reconcile regression harder to attribute."* The empty-behaviour
   changelog argument that justified giving it its own release still binds.
2. **My slice sizing was badly wrong.** I floated 3 slices; the reviewer would not review that
   honestly. The bound is **~5–8 functions or ~400–700 lines, whichever comes first**, grouped by
   one responsibility.
3. **My ntfy wording was dangerously ambiguous, and it read it the right way.** *"Fire-and-forget
   with a bounded timeout"* can mean awaiting an HTTP call on the send path. For an external
   network dependency that is not acceptable: it must be **off the request path entirely**.

# v0.3 — Desktop notifications

*"i want dashboard to use notices system … so i would hear when i would get message from agent."*

**No server change.** The dashboard already holds a `/ws` WebSocket with backoff, and the service
already broadcasts `message_sent` with `{id, from, to, subject}` (`api_v2.py:17040`) and
`channel_message`.

**No TLS work.** `localhost` is a secure context, so `http://localhost:8801` on the machine itself
gets full `Notification` support with zero infrastructure. (This corrects my earlier claim that
HTTPS was required — that applies only to phones.)

- [ ] New pure module `service/new_dashboard/notify.mjs` with `notify.test.mjs`. Behaviour goes
      here, not in `app.js` — that file is ~4.9k lines and only reachable by source-regex tests,
      which cannot fail on wrong logic.
- [ ] Permission requested on an explicit user gesture, never on load.
- [ ] **Dashboard-addressed messages only.** 3,883 messages in 14 days; notifying on all fleet
      chatter makes the feature unusable in an hour.
- [ ] Suppressed while the tab is focused.
- [ ] Off by default; persisted opt-in toggle.
- [ ] Coalesce bursts — the measured shape is 2-agent ping-pong at ~2–4 minutes per message.

**Acceptance:** a message sent to `dashboard` from another agent raises exactly one notification on
an unfocused tab, and none when focused or when the toggle is off.

# v0.3.x / v0.4 — Mobile alerts via ntfy

Web Push is the wrong tool: service worker → secure context → TLS on a LAN address, for a service
that is explicitly run locally in a container. **ntfy is one outbound POST**, no PWA, no VAPID, no
subscription table.

**The delivery contract, which is the part that needs to be right:**

- [ ] **Off the request path entirely.** Not "await with a short timeout" — the send handler
      enqueues after commit and returns. A background worker drains the queue.
- [ ] Bounded timeout on the outbound POST, in the worker.
- [ ] Failure is logged and dropped; it must never fail, delay, or retry-storm the message it
      reports. This hooks the fleet's hot path.
- [ ] Coalescing / rate limit, same reasoning as v0.3.
- [ ] `notify_ntfy_url` lives in `.env`, never `config/service.json`. It is a **secret** — anyone
      with the topic can read every notification — so it must be redacted from logs and absent from
      `/settings` responses.
- [ ] Default OFF; empty URL = disabled.

**Not started until the queue contract above is written as a design and reviewed.**

# Own release — Extract the reconcilers

43 functions, **3,530 lines, 15% of `api_v2.py`** (23,323 lines). `main.py`'s sweep imports 28 of
them, so the manifest is code-declared rather than invented. Two of v0.2's bugs lived in this seam.

**Target:** `service/reconcilers/`, one module per responsibility.

cheaply if the gate turns out to be wrong.

## Per-slice gates

*"The safety net is 'running service behaves the same', not 'pytest saw the same functions'."*

- [ ] **Pure moves only.** No behaviour change in a move commit.
- [ ] Container rebuilt, `aify-doctor` green.
- [ ] Pre/post **route inventory** diff.
- [ ] **Import-identity check**: no second `_LIVE_STATE_CACHE` / `_LIVE_SCREENS` instance. The
      single-worker invariant is untouchable; a duplicated module-global silently forks state.
- [ ] **One live smoke replay through the moved seam** against the running service.
- [ ] Before/after API responses for representative endpoints from a seeded DB.

**The reviewer's test for a too-broad slice:** if it cannot name *one* seam smoke replay and *one*
representative before/after API readback, it is too big. Each slice above must name both before it
starts.

**Non-goal:** rewriting logic while moving it. If a move surfaces a defect, card it and move on.
