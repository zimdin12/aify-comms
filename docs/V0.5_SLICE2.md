## Verdict: one slice, unlike slice 1

Slice 1 had to split because `_refresh_expired_agent_live_states` reached the status-computation
core. Nothing here does. All three blocking helpers are small and dependency-free:

| helper | lines | deps | destination |
|---|---|---|---|
| `_iso_to_epoch` | 9 | none | `service/clock.py` — it is a timestamp parser, and `now()` already lives there |
| `_invalidate_agent_live_state` | 9 | none | `service/reconcilers/status_cache.py` — it is a CACHE operation and belongs with the cache it invalidates, which slice 1a already moved |
| `_environment_effective_status` | 25 | none | leaf module; `api_v2` imports it back, which is safe for a function (no cycle — the leaf never imports the router) |

`_invalidate_agent_live_state` moving to `status_cache.py` is the part worth noticing: it is not a
workaround for the seam, it is where that function should have been all along. Slice 1a moved the
cache; this moves an operation on it to sit beside it.

## `_load_settings` — the same seam as slice 1a, and the same answer

`_fail_orphaned_running_spawn_requests` reads settings. Reviewer-approved pattern from slice 1a:
a pure derivation helper, the caller computes the scalar from the pass settings, the callee receives
it. Required parameter, not optional — slice 1a's hardening showed that an optional default whose
meaning changed after a move is a footgun that reads as backwards-compatible.

`_finalize_spawns_with_dead_terminals` already takes `grace_seconds` and falls back to
`SPAWN_DEAD_TERMINAL_GRACE_SECONDS`, so it has the scalar seam already; make it required on move for
the same reason.

## Gates and proofs required in the slice-2 commit

The three standing gates (sweep-ordering, import identity, route inventory) plus what the reviewer
specified for this slice in particular:

- [ ] **AST body-compare** proving each moved body verbatim, or the seam named explicitly. The
      reviewer verified slice 1a this way; it is the cheapest honest proof of a move.
- [ ] **Import-cycle smoke**: `create_app()` builds.
- [ ] **Spawn-lifecycle readback, not status endpoints.** Status endpoints cannot see spawn-row
      behaviour. Needs before/after over `spawn_requests`, `agent_sessions`, and the
      terminal/session correlation, covering queued→claimed→running, restart, cancel and failure.
- [ ] **Sweep order preserved**: `_finalize_spawns_with_dead_terminals` must stay BEFORE
      `_fail_running_spawns_superseded_by_current_session` — that ordering is the fix for the
      2026-08-07 spawn that sat `running` for 97 minutes because the superseded reaper needs a newer
      live session to exist and the dead-terminal path needs no successor. The sweep-ordering gate
      already asserts this pair; it must stay green through the move.
- [ ] **Commit ownership unchanged** — do not tidy which function commits, as in slice 1a.
- [ ] **No compatibility aliases**, and `GLOBALS`/import updates in the same commit if any global
      relocates.
