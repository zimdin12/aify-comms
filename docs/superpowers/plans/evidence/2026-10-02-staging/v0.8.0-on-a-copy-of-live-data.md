Why: the live service could not be taken down (a team was working), so v0.8.0 (comms 3811a66f) ran as a
separate compose project on a consistent copy of the live database.

Isolation, from `docker compose -p aify-comms-staging config` before anything started: containers
`aify-comms-staging-service` / `-dashboard-next`, ports 8820 / 8821, network `aify-comms-staging-network`, volume
`aify-comms-staging-data`, restart `no`. The volume name is NOT project-scoped in docker-compose.yml
(`${DATA_VOLUME_NAME:-aify-comms-data}`): without `DATA_VOLUME_NAME` a staging stack mounts the LIVE volume.

Copy: SQLite backup API from `/data/aify.db` opened read-only inside the live container, to its /tmp, copied out,
removed. quick_check ok; 40 agents, 41694 messages. Seeded into the staging volume before first start, uid 1000.
