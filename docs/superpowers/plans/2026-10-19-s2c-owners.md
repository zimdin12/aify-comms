# S2c: the other nine C8 owners (2026-10-19, revision 3)

Status-switch plan S2, its remaining half. Only the status word is measured today (S1, S2a, S2b, Q3,
awaiting-input). C8 needs all ten decisions measured in the same evaluation, on the same rows, with a nonzero
denominator each. Revisions 2 and 3 answer comms-senior-dev's REVISE_PLANs (R1 to R4): a candidate is computed from history it
retained itself, never rebuilt from today's rows.

## Three parts, each its own owner

**1. The recorder, per owner (prerequisite, R2).** Today `Recorder.record` and `ShadowWindows.tick` are word-only
(`OWNER='status word'`). They take an **observation**: `owner` (one of C8's ten), `variant` (busy's `strict` and `P-1`;
`-` for the rest), `site`, the versions, and today's and the candidate's answers. Pending counts, unavailable reasons,
classes and window rows are keyed by `(owner, variant, site)`. The report lists every owner and variant, and one never
observed reads `instrumented: false`. Witness: a busy comparison and a busy unavailable persist under busy and leave the
word's denominator unchanged.

**2. `DeliveryTurns`, the candidate's retained state (R1).** One in-memory object per agent, shadow-owned. It never
writes `agent_turn_state` or any other legacy row. It folds C6's merge rules as their inputs arrive:

- a delivery reporter's busy or clear for run R, at the same handler that writes today's row;
- an applied env record whose turn advanced. Advanced means `lastEventAtUs` moved against the last one this fold saw,
  not `row_applied_at`, which the receiver rewrites on every snapshot. This touches the turn and is the 120 s
  last-advance anchor;
- an applied env record whose turn ended, which closes it.

It also keeps the **earliest start estimate** per turn (`appliedAt - ageMs`, keyed by `startedAt`), for `strictExpiry`,
and the reporter's bridge id, which today's renewal check needs.

**Knowledge per field (R1, revision 3).** Each field is known or unknown: `open`, `runId`, `startedAt`, `touchedAt`,
`owner`, and each turn's estimate. After a restart the fold is seeded from today's row with every field **unknown**.
Only these transitions establish a field; any other event leaves unknown fields unknown:

| transition | establishes |
|---|---|
| env turn-end | closed, so every turn field is known (a closed turn has none) |
| reporter clear for R, while `runId` is known to be R | closed, likewise |
| reporter busy for R | `open`, `runId`=R, `touchedAt`, `owner`; `startedAt` only when the fold knew it closed |
| env advance | `touchedAt`, only when `open` is already known true |

So these establish nothing:
- an env advance on a seeded open turn;
- a reporter clear while `runId` is unknown (it might or might not close);
- a wrong-run clear.

A turn's estimate is authoritative only when the fold saw that turn begin: its first application with a new
`startedAt` after the fold knew the previous turn was closed. A turn already running at the seed has no authoritative
estimate, so its `strictExpiry` stays unknown until it ends. A later estimate never stands in for a lost one. A restart
already closes the window ('service-restart'). A candidate that needs an unknown field counts `unavailable:seeded`.

**3. `commsView`, pure, with three-valued knowledge (R3).** `commsView(records, delivery_turn, messaging) -> View`.
Each output is true, false or unknown, and an unknown is never counted as false. `holdsDelivery` is the OR of C6's
disjuncts:
- the fresh record's busy;
- the delivery turn, held only while open **and** `turn_is_still_live` on its own anchor (R4). It is
  `strict_seconds=1800`, measured from `startedAt`, or from `touchedAt` when renewable. Renewable means today's
  `_turn_lease_is_renewable` for the fold's `owner`. When that owner is the one today's row names, the candidate reuses
  the value today's gate just computed; otherwise it is one more query, counted. The disjunct is unknown when an
  anchor or the renewal is unknown. An open turn past its bound with no renewal is **false**: a raw open never holds
  for ever. Raw `open` and `runId` stay separate outputs for the stranded guard and run correlation;
- a stale record's open turn before `strictExpiry`.

It is true when any disjunct is true, false only when all are known false, and otherwise unknown. Without `ageMs` the
stale disjunct is unknown, so the result is still decided when another disjunct is true. A consumer is unknown only when
the unknown input could change its answer. For example, the queue is decided when `runOccupied` already queues. An
unknown result counts `unavailable:<input>`.

## Owners

| owner | today, unchanged and still returned | candidate |
|---|---|---|
| busy (`strict`, `P-1`) | `claim_gating._turn_busy_holds_delivery` | `holdsDelivery` |
| send-time queue | `dispatch_launch` queueIfBusy | the same rule on `holdsDelivery` / `runOccupied` |
| claim | the `/dispatch/claim` gate, steer and non-steer | the same on `holdsDelivery` |
| reminder skip | `dispatch_sweeps` `turn_fresh and turn_run_id != run` | C6's expression on the fold |
| stranded-reply guard | the busy row with this run id | the fold's turn open on this run |
| worker readiness | `channel_delivery._worker_liveness_for` | `process` and `deliverable` |
| live counts | `is_live_agent_status(word)` | the same on the view's word |
| running-run promotion | `records._status_with_dispatch`, where applied | C6 row 5, at the same sites |
| stale-turn ceiling | 1800 s from receipt of turn-start | `strictExpiry` from the fold's earliest estimate |

**Isolation.** The whole capture, compute and record step runs after today's answer, inside one `try`, and never
reorders today's side effects. A raise counts `unavailable:<reason>`. One test per site forces a raise and asserts the
decision and its side effects are identical. Each slice names and measures any DB query it adds to the claim path.

## Slices, one review each

1. The recorder per owner (part 1).
2. `DeliveryTurns` (part 2), with these controls:
   - end-then-start with the legacy close missing: the candidate stays closed for R while today's row says open;
   - a quiet snapshot that does not move the anchor, against a true advance that does;
   - a healthy reporter reopen;
   - a seeded open turn, then an env advance: still unknown;
   - a seeded open turn, then a wrong-run clear: still unknown;
   - a known close, then a reporter reopen: known, with a known start;
   - a turn running at the seed: no `strictExpiry` until it ends.
3. `commsView` and the busy owner, with five controls:
   - a missing age leaves busy unknown;
   - a present age decides it;
   - a fresh busy record decides it while the age is missing;
   - a known-live delivery turn decides it while the age is missing;
   - an open delivery turn past its bound with no renewal is false, against one with a valid renewal, which is true.
4. The four busy consumers: queue, claim, reminder skip, stranded guard.
5. Worker readiness, live counts, running-run promotion (design rev2, approved 10-19). Its coverage is bounded,
   and these limits are part of the slice:
   - **Promotion is instrumented at today's three sites only** (serialize, preflight, buffer-full). The word paths
     (engine-status, cache-broadcast, refresh) are UNINSTRUMENTED for promotion: C6 promotes there and today does
     not, and no word disagreement shows it (a fresh `idle` record and today's `online` agree on the word while a run
     is running). Measuring them needs `dispatch_state` at those evaluations, which is a separately reviewed
     "promotion on every path" slice, required before C8 qualification.
   - **Rows 2 and 2b (D8) are not implemented.** A missing record is unknown (`no-record`) wherever the two rows
     would answer differently; this gap is disclosed, not qualified.
   - **Row 1 is withheld, not decided.** comms' stop flag makes it possible, and the answer is unknown
     (`operator-stop`) only where row 1 would change it.
   - Readiness's delivery read is bounded to one attempt of the branch's own component, only when it can change the
     answer.
5E. **S2c-E, disagreement evidence** (a separately reviewed slice, a prerequisite of slice 6 and of C8
   qualification). C8 needs every disagreement's raw inputs and the three repositories' versions, and anonymous
   tallies cannot classify one at any volume. The slice binds, per disagreement: the same evaluation's identity and
   time; owner, variant and site; both answers; both sides' frozen raw inputs; and all three versions, each known
   or unknown. It defines what payload is retained, and what happens on eviction, loss, restart and a version
   window. Bounded examples may help diagnosis but never qualify evidence that was lost. Unseen-class controls
   (slice 7) cannot attribute disagreements already observed.
6. B6 in aify-env: `build` and `turn.ageMs`. The receiver rejects unknown fields (`agent_state_shadow.py:39`), so the
   comms receiver ships first, accepting both as optional. The wrapper schema copy follows, then aify-env publishes.
   Each step works against the previous one; the sibling suites run with `AIFY_ENV_REPO` set to the candidate. Then
   the age paths go live and the ceiling owner is measured.
7. C8's unseen-class controls, through `commsView` and the fold.

## What would prove this wrong

- A merge rule whose input arrives where the fold cannot see it, such as a reporter path that writes today's row
  without passing the handler. The fold then needs that capture point, and this plan gets a row.
- An owner whose candidate is unknown on nearly every evaluation once B6 is live. That means a knowledge rule is
  stricter than C6 needs.
