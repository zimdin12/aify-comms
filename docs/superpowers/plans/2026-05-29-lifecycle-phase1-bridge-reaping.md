# Lifecycle Phase 1: Bridge Reaping & Bridge-Death Reap — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make every managed backing process reliably die when its terminal is stopped and when the environment bridge exits, so no orphaned wrapper/gateway/app-server processes survive.

**Architecture:** The Node bridge (`mcp/stdio/`) owns managed worker processes. We (a) route every PTY kill through `terminateProcessTree` (process-group kill, not bare SIGHUP), (b) add `shutdownAll*` reapers for codex/hermes session pools and wire them into the bridge's SIGTERM/SIGINT path next to the existing pi reaper, and (c) fix the hermes/codex wrappers so the dashboard gateway dies with the wrapper's process group instead of being detached into its own session by `setsid`.

**Tech Stack:** Node.js ESM (`mcp/stdio/*.js`), `node --test`-style assertions run via `mcp/stdio/tests/run-all.mjs`, bash wrapper heredocs generated by `install.sh`.

**Spec:** `docs/superpowers/specs/2026-05-29-managed-session-lifecycle-design.md` (Phase 1 = root causes B + bridge half of A).

### Task 5: PTY stop uses `terminateProcessTree` (kill the wrapper group, not SIGHUP)

**Files:**

- [ ] **Step 1: Write the failing test** — assert the PTY stop path issues a group kill, using a fake pty whose pid is the current test process's child.

```js
#!/usr/bin/env node
import assert from "node:assert/strict";
import { spawn } from "node:child_process";
import { TerminalProcessManager } from "../terminal-runtime.js";

// Spawn a real, long-lived child in its own group to verify tree-kill reaps it.
const child = spawn("sleep", ["120"], { detached: true });
const mgr = new TerminalProcessManager({ onOutput: async () => {}, onExit: async () => {} });
// Inject a fake pty terminal whose `term` proxies the real child pid.
mgr.terminals.set("t1", {
  id: "t1", kind: "pty", exitPromise: Promise.resolve(),
  term: { pid: child.pid, kill: (sig) => { try { process.kill(child.pid, sig); } catch {} } },
});
await mgr.stop("t1", "test");
await new Promise((r) => setTimeout(r, 400));
let alive = true;
try { process.kill(child.pid, 0); } catch { alive = false; }
assert.equal(alive, false, "child process group should be reaped by stop()");
console.log("terminal-runtime-pty-kill.test.js: all assertions passed");
```

- [ ] **Step 3: Switch the PTY kill to tree-kill**

with:
```js
    if (terminal.kind === "pty") {

      try { terminateProcessTree(terminal.term, "SIGTERM"); }
```

### Task 6: Wrapper gateway joins the wrapper's process group (so it dies with it)

**Files:**
- Modify: `install.sh` (hermes wrapper heredoc — the `setsid ... hermes dashboard ... &` spawn ~1496-1501; traps ~1513; codex wrapper trap ~467)

**Why:** `terminateProcessTree` kills the wrapper's process group. The dashboard gateway is spawned with `setsid`, putting it in its OWN session/group, so the group kill cannot reach it. Spawning it WITHOUT `setsid` (still detached from the TTY via `</dev/null` and log redirection) keeps it in the wrapper's group → group kill reaps it. Keep the cleanup trap as a belt-and-suspenders and add `HUP`.

- [ ] **Step 1: Drop `setsid` for the gateway spawn (stay in-group), keep stdio detached**

In `install.sh`, find the hermes wrapper heredoc block that spawns the dashboard (search `dashboard --tui --port`; the `if command -v setsid` / `else` pair, ~1496-1501). Replace the `setsid`-based branch so BOTH branches spawn in the wrapper's own process group:
```bash
  "\$HERMES_RUNTIME_COMMAND" dashboard --tui --port "\$AIFY_HERMES_PORT" --host 127.0.0.1 --no-open --skip-build </dev/null >>"\$AIFY_HERMES_DASHBOARD_LOG" 2>&1 &
  AIFY_HERMES_DASHBOARD_PID=\$!
```
(Remove the `setsid`/non-`setsid` conditional; always use the plain `&` form. `</dev/null` keeps it off the wrapper's TTY without a new session.)

- [ ] **Step 2: Add `HUP` to the hermes wrapper cleanup trap**
