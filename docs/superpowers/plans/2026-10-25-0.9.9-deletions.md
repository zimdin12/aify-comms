# 0.9.9: deleting what the status switch left behind (2026-10-25)

This builds SW7 of `2026-10-20-s4-hard-switch.md` (page 3, "Deletions") against the code as it stands on
2026-10-25. The switch has been live since 2026-10-23. The operator reported two status faults on 2026-10-25
(fixed in aify-env 632a0c7/644f9e2 and comms d89dd543) and called it "overall quite good", then said to carry on.
That is the rollback gate the plan asks for.

## What goes, in three slices

**S1, the comparison apparatus. No relaunch.** Built to qualify the switch (classes B and W of page 4), it decides
nothing. Removed:
- the recorder and everything only it reaches: `shadow_classes`, `shadow_evidence`, `shadow_evidence_store`,
  `shadow_owners`, `shadow_provenance`, `shadow_windows` (and its periodic task in `main.py`), `busy_consumers`,
  the `comms_view` module, `stale_turn_ceiling`, the `delivery_turns` fold, and the observers in `view_owners`;
- their calls at the live sites: `shadow.observe` (status_broadcast, status_inputs, status_refresh), the
  `view_owners.observe_*` calls (analytics_series, analytics_summary, channel_delivery, dispatch_runs, records,
  registration_gates, send_preflight, status_inputs), and the recorder and fold calls in `agent_state_shadow` and
  `routers/agents/liveness.py`;
- the three `/agent-state/shadow-*` routes, the `status_shadow_*` tables (dropped by migration), and the
  `agent-state-shadow` doctor row. An operational row replaces it: per host, whether its publisher is fresh, stale,
  restored or unavailable.

Kept, because live readers use them: the mirror and `bind` in `partial_status_shadow` (renamed in S3),
`candidate_word`, `PROMOTABLE` (moves into `operational_view`), `mirror_restore`.

S1 is done: b8ee0cb0, live 2026-10-25. The D-UNKNOWN reader (`delivery_unknown_report`) went too, as it read
only the dropped window tables. On the live service, `/agent-state/shadow-report` answers 404, no
`status_shadow_*` table remains, and the doctor's `agent-state-publishers` row reads "2 of 2 publisher(s) fresh".

**S2, the legacy turn path. One relaunch.** Launchers post turn events to aify-env only (aify-wrapper hooks). The
comms turn routes (`routers/agents/turn_boundaries.py`, the liveness turn fields) answer 200 and ignore, so a
launcher not yet relaunched fails nothing. The bridge's turn detectors go
(`claude-turn-end-detector.js`, `claude-turn-detector-state.mjs`, `hermes-gateway-turn-detector.js`,
`hermes-turn-detector-callbacks.mjs`) once no route reads what they post.

**S3, the legacy engine.** `status_engine.derive` and its inputs (`status_inputs`, `status_events`, `turn_state`,
the legacy columns and the `legacy_status` cache field), after a proof that no live route reaches each. The status
vocabulary (`VALID_STATUSES`, `NON_LIVE`, `is_live_agent_status`) moves to one small module, since the view and the
dashboard read it. The two agent-state tables are renamed out of `shadow`, with a migration, and the rows table
loses `row_applied_at`: since S1 it is written and never read. A database backup is
taken before this slice and deleted once it is verified, as the operator wants no backups kept.

## Each slice

1. Every module is deleted only after a search proves nothing outside it and its tests reaches it. The search is
   controlled: it must find a module known to be referenced.
2. Tests that only test removed code go with it. A test whose obligation survives (the switch witnesses, page 2) is
   rebased onto the view, never dropped.
3. All five suites pass; the service is rebuilt and both doctors read as before or better.
4. dashboard-manager reviews the 0.9.9 diff before the tag (agreed 2026-10-25).

**Done when:** none of the names above exists outside git history; the dashboard's status, the claim gate and the
queue behave as on 2026-10-25 (watched for a day of normal use); `aify-comms doctor` has no `agent-state-shadow`
row.
