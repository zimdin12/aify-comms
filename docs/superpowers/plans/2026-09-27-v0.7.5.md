# v0.7.5: the operator's open list after the 0.7.4 tag (2026-09-27)

The operator said "carry on, whole list" after v0.7.4 was tagged at 09147377. This file is the list and
its state; a loop resumes from it, so update the status line of an item in the same commit that changes
it. Each item: every suite green, mutation-proven where it is behaviour, commit and push per item. Tag
v0.7.5 only after comms-senior-dev APPROVE; deploy is the operator's.

Operator rulings this list rests on (2026-09-26/27):
- Agents may work as long as the work needs; limits are by state, never by time ("why even have a cap").
- Any API-key holder (not an external key) may do lifecycle actions; the API key is the trust surface.
- The operator key should be off by default.
- Tell the operator only what they ask for, or when something actually went wrong.
- Delete `comms_dispatch`, `comms_listen`, `comms_dashboard`, and `comms_clear`'s whole-hub wipe.
- Compaction: offer the runtime's own `/compact`; the reset variant should point the agent at its last
  messages and its previous session, not inject a transcript.
