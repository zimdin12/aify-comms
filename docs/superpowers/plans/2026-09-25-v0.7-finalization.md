# v0.7 — the finalization pass

**Asked by the operator, 2026-09-25:** "I want this project to get a big update on every layer … scan
each component with different lenses, combine your findings, improve the shape, architecture, fix bugs,
fix docs and skills, improve dashboard, improve TUI … mostly low hanging fruits … this project is not
going to get too many updates in the future, so we finalize it as 0.7.x … use ponytail also … and in
the end use senior dev for code review."

## Decisions (reversible, stated so they can be overruled)

- **Scope:** aify-comms is the target. aify-env is in scope for the TUI only (attach, the Herdr
  integration, the console the operator types into), because that is where the TUI lives. aify-wrapper:
  docs only.
- **Version:** aify-comms goes to 0.7.0. aify-env goes to 0.7.0 only if it changes.
- **Nothing is deployed until the end.** v0.6.21 and v0.6.22 are unreleased on this host and ride along.
- **Low-hanging fruit only.** A finding that needs a design, a migration or an operator decision is
  written down in the backlog section below, not built.

Every finding carries: file:line, the concrete failure or cost, evidence read, severity (P1 breaks
something / P2 real but minor / P3 polish), and effort (S under an hour / M / L).

## Then

1. Triage every finding into: FIX (S or M, clear value, no operator decision), BACKLOG, or REJECTED
   (with the reason). Recorded in the table below.
2. Fix in slices, one subject per commit, each with its test watched red first, all five suites green.
3. comms-senior-dev reviews the whole diff since v0.6.22; its findings are fixed or answered.
4. Bump to 0.7.0, tag. Deploy is the operator's call.

## Done when

Every finding is triaged, every FIX item is committed with a test that fails without it, the review
is closed, and `v0.7.0` is tagged on a green tree. Anything found after triage that is not a P1 goes to
the backlog rather than into this release.

### Decisions taken here (reversible; each is one commit to undo)

- **F1:** Ctrl+C in menu/start/picker backs out of that mode. In dashboard mode on the daemon, it asks
  "stop the environment and its N workers? y". A signal-delivered SIGINT is unchanged.
- **C6:** the Environments page names `aify-env` and `aify-env doctor`. "Stop bridge" goes, because
  `/environments/controls/claim` has no remaining claimer (D23).
- **B4:** `--delegate-spawns` is retired. aify-env is the only spawner, so `spawn-delegation`
  becomes "is the aify-env serving this host answering", probed unconditionally.
- **B2:** each bridge sends its `bridgeBuild` when it registers; the service stores it on the
  bridge's `bridge_instances` row, and `GET /bridges` lists the live ones for `bridge-current`. A
  bridge instance, not an agent row, because one agent can have several live bridges. Until a bridge
  started on 0.7.0 reports a build, the row reads `unknown-all`, not ok.
- **A10:** `service/control_plane.py` is deleted, and the gates that use it as a witness are
  re-aimed at the real owners.
- **A16:** the v1-to-v2 JSON migration tooling is deleted (the pre-SQLite era; git keeps it).
- **A1:** `/clear` applies `olderThanHours` to each target that has a timestamp, and under a cutoff
  leaves alone the tables only `all` clears. `target` is a closed set; anything else is a 422.

### Rejected

- **B20** (split `pi-session.js`): pi is deprecated. Touching it only to make room is churn.

  git a `/c/...` path, so the stamp reads no checkout and records sha `unknown`. Pre-dates 0.7; the
  test seals those variables out. Running git from `cd "$REPO_ROOT"` instead of `-C` would fix it.
