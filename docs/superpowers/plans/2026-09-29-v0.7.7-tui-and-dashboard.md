# v0.7.7: the terminal UI and the dashboard

The operator's goal for this release: "we need to make our tui stuff really well ... good and fast",
"starting agent maybe should open something that has a search", and "in dashboard some of the
elements and things are badly built and have bad UI + UX. some stuff even have issues."

v0.7.7 also carries the external review's round-3 fixes (aify-comms 6a8e2fce..1d719367, aify-env
be3e003), which are deployed locally and in review.

## How the list was chosen

The 2026-09-29 UX audit (`2026-09-29-tui-and-dashboard-ux-audit.md`) is the source. Two read-only
code checks re-read every item at aify-comms 1d719367 and aify-env be3e003 today, and one rendered
the terminal UI from `lib/tui.mjs` at 100x24 with 12 agents. Items that no longer hold are marked.

Each item below is the smallest change that fixes what the operator sees. An item that only
restructures code is in the cut list at the end, unless an item here cannot land without it.

## Speed, measured first

The attach lag came from one `icacls` spawn per credential read (fixed in aify-env 4044364). It went
live with the operator's aify-env restart today. `/health` on the live daemon, 957 requests over
60 s, all answered: p50 1.3 ms, p90 1.9 ms, p99 3.8 ms, one request at 392 ms. The measurement
before the fix was p90 290 ms, p99 1.6 s, max 3 s. Fewer agents run now than then, so the load is not
identical. No speed work is planned. If the operator still feels lag, the keystroke path gets
measured hop by hop before anything is changed.

## Part 2. Terminal UI

1. **A searchable start list.** This is the operator's example. Today `s` draws a list below the
   table that takes arrows and j/k, with no filter and no way out but Ctrl+]. At 100x24 it shows one
   agent of 18.
   - `s` opens the list in place of the agent table. Typing filters it, and the list shows "N of M".
     Enter starts the selected agent. Esc closes the list.
   - The process finder already edits a query, takes a paste and counts "N of M"
     (`lib/keys.mjs:345-378`, `#handlePaste`, `visible()`). The filter moves into one small pure
     function that both lists call, so the two cannot drift apart.
   - A bare Esc is told apart from the start of an arrow key by the same short timer the paste
     handler already uses.
   - Each row says why the agent cannot start, when it cannot.
   - After Enter, "starting sc-manager..." stays on the outcome line (item 3) until the worker
     appears.
   - The picker is a new module. `lib/tui.mjs` is 974 lines against the 1000-line gate.
2. **Agents get the space.** At 100x24 with 12 agents the table shows one row, because SERVICES,
   HEALTH, RECENT EXITS and TRAFFIC always render in full (`renderDashboard`, `lib/tui.mjs:927`).
   The fitting pass will first collapse those four sections to one line each, and only then shrink
   the agent table. The check renders 100x24 with 12 agents and requires all 12 rows.
3. **One outcome line that fitting never drops.** Start and stop results go into NOTICES today, and
   NOTICES is the first section trimmed, so a result vanishes at 24 rows. The newest result sits
   above the hint line. NOTICES keeps the history.

## Part 3. Dashboard

1. **Start an agent from one search box.** Today there are five ways to start or spawn, none with
   search, and the spawn form's Agent ID is free text.
   - A "Start agent" button in the top bar, or Ctrl+K, opens a dialog with a search box over every
     agent and its status.
   - Enter does the one action that fits the agent's state. A stopped or available agent is
     started through the existing `POST /agents/{id}/control` start. A running agent opens its
     console.
   - A name that matches no agent offers "Create", which opens the existing Environments spawn form
     with the ID filled in. There is no second create form.
   - The agent's status updates through the normal refresh, so there is no separate progress card.
2. **The drawer offers what the agent's state allows.** It shows up to 11 buttons, only Stop depends
   on the state, and there is no Start, although the Stop confirm says "you can start it again". One pure function in
   `agent-drawer.mjs` returns the actions for a status. Start appears for a stopped or available
   agent, and Stop only for a running one.
3. **One status list everywhere.** The Chat status chips are hand markup missing `starting` and
   `misconfigured`, so a newly spawned agent disappears under any chip filter. The Help legend says
   "six agent states" where there are nine. The "Working now" tile is blue while the working dot is
   amber. The chips and the legend will be generated from `AGENT_STATUSES` (`status.js:35`), as the
   Sessions chips already are, and the tile uses the working colour. The existing colour test will
   cover every status, not only the chips that exist.
4. **The Chat rail says what its filters hide.** It shows "No agents." when a filter hides
   everything. It will show "N hidden by filters · Clear", as the Sessions rail does.
5. **A closed drawer leaves the Tab order.** One CSS rule, `visibility: hidden` on the closed
   drawer, takes its buttons out of keyboard focus without touching the seven places that open it.

`styles.css` is at 1851 lines under a fixed ceiling, so any CSS added here removes as many lines
elsewhere in the file.

## Order

The bugs first, one commit each. Then terminal UI items 1 to 3, then dashboard items 1 to 5. Every
item lands with the test that fails without it, watched red before the fix.

## How each item is checked

- **Terminal UI.** The frames are rendered from the pure `lib/tui.mjs` in Node at 100x24 and 80x24,
  with 12 and 30 agents, and the tests assert row counts and hint text. No daemon is started.
- **Dashboard.** Module tests with a stubbed `document`, the pattern the dashboard suite already
  uses. The live dashboard is not click-swept.
- **After deploy.** `aify-comms doctor` and the served assets confirm the build. The operator looks at
  the result, since the live dashboard needs the API key.

## Cut from v0.7.7, and when each would be added

- **One key map per TUI mode, nested overlay state, a separate UI palette.** T1 is fixed directly.
  Add them when a second hint defect appears.
- **`?` help, column priorities, attach by prefix or picker.** Add them if the operator asks.
- **A drawer owner module with focus return.** Item 5 covers the Tab order. Add focus return if
  keyboard use of the drawer matters.
- **Removing the dead `flowGates` and the duplicate slice appliers.** These are internal and not
  visible to the operator. Remove them the next time those modules are touched.
- **Mobile layout, reorganising `styles.css`, several consoles side by side.** These are large, and
  nobody asked for them.

## Decision for the operator

In the start picker, j and k will type into the search, as they already do in the process finder,
and the arrow keys will move the selection. Say so if you want j and k to keep moving.
