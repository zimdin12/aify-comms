## 1. The configured model reaches the agent's next start

What happens today:
- A start already passes the definition's model and effort to the harness. A managed launch sets
  `AIFY_MANAGED_MODEL` from the definition (`definition_start.spec_columns`), and each launcher reads it, or the
  definition itself for a resident start (`aify-wrapper` `wrappers/*-aify.sh.in`, `claude_aify_defaults`). SOURCE
- A definition with an empty model means "the harness default", and then the launcher passes no `--model`.
  23 of 24 definitions are empty. OBSERVED 2026-10-04
- Claude Code restores a resumed session's model from its transcript unless `--model` or `ANTHROPIC_MODEL` is
  given at launch, and aliases such as `opus` resolve at request time. DOCS
- So changing Claude's default model never reaches an agent that resumes. sc-lead, mc-manager and llama-manager
  kept `claude-opus-5` after `opus` moved to `claude-opus-5-5`. OBSERVED 2026-10-04

Slices:
- **1a.** A Claude launch that resumes and selects no model passes the harness default explicitly, so the
  resumed session runs what the configuration says now. The value is the one Claude itself would use for a new
  session: `ANTHROPIC_MODEL`, else the user settings' `model`. With neither, the launch passes nothing, as today.
  aify-wrapper `claude-aify`.
- **1b.** Codex and hermes, the same question measured first. Hermes follows its configured default inside a
  session (OBSERVED 2026-10-04, M9), so it may need nothing. Codex `thread/resume` with an empty model is unmeasured.
- **1c.** Bulk set: `aify-env agents set --all|--harness <h>|--ids a,b model=X [effort=Y]` prints each agent's
  before and after, writes only with `--yes`, carries each definition's expected revision, and skips an agent
  whose definition changed meanwhile.

## 2. Same-id handoff compaction

A handoff into the same id is refused for a defined agent (KNOWN_ISSUES, D8). It becomes a fresh-context
lifecycle `restart` that carries the handoff brief: `agent_lifecycle_requests.brief` already exists and is
delivered once on attach.

## 3. Actual-model visibility

As planned in `2026-10-04-configured-vs-actual-model.md`: aify-env reads the model each lifetime actually runs
(the Claude transcript tail, the hermes `state.db` usage row, the codex rollout), publishes it in the agent-state
feed, and comms shows the desired and actual values side by side. A missing or stale reading is UNKNOWN, never a
mismatch. Nothing switches automatically.

## 4. Test stability

`test_resident_hooks_reach_the_service_authenticated.py::test_g5_*` (3 s hook deadline) and the bridge's
`hermes-gateway-readiness-names-its-stderr.test.js` fail under suite load and pass alone. Each gets its budget
measured against its own cost (CLAUDE.md: "flaky" usually means a budget below its own cost).
