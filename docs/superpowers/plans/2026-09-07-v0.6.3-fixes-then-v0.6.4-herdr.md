# v0.6.3 — fixes only, no new surface

## A. THE SIDE PANE CANNOT RENDER A TUI. Root-caused 2026-09-07.

The operator pasted a live `aify-env tui`. The right-hand pane read:

```
│ Cited file didn't exist.—eflaggedCtheTbrokentpointer
│ · Misting… (5m 45s)
│     insurance, not mis_llocated effort.
```

Characters from different screen positions concatenated onto one line. **Not a width bug.**

`lib/pane-buffer.mjs` models exactly two things: `\n` ends a line, `\r` returns to column 0. Its own
header says so. A coding agent draws with **cursor addressing** — `ESC[row;colH`, `ESC[K`, `ESC[J`,
`ESC[A/B/C/D`, scroll regions — and replaying that into a line model concatenates fragments that were
never on the same row.

**aify-comms already learned this and wrote it down.** `service/api_core/console_prompts.py`:

> *"claude does not send spaces, it moves the cursor ... so a matcher run on raw bytes is looking for
> a string that is never transmitted. It watched the dialog it was written for and did nothing, with
> every one of its tests green."*

That is why the service renders through **pyte**, a real terminal emulator. aify-env's pane never got
that lesson. It is the same defect, one repo over.

**Why `attach` looks fine** — the operator confirmed it does — is that attach pipes bytes to a REAL
terminal, which emulates. The preview is the only thing pretending.

**Three ways out, and this tag takes the third:**

1. Put a terminal emulator in aify-env (`@xterm/headless`). Correct, and it ends the zero-dependency
   posture for a preview pane that v0.6.4 deletes.
2. Hand-roll one. No — that is the mistake this whole plan exists to stop making.
3. **Make the preview honest.** Detect a cursor-addressed stream and show a short true line —
   *"live TUI — press Enter to attach"* — plus the last plain-text lines if there are any. A pane that
   says what it cannot show beats one that shows a scramble and looks broken.

v0.6.4 removes the question: herdr renders panes with a real emulator, which is the point.

Suspects, in order: `sideBySide` pads the left column to `leftWidth` but `frameUpdate` writes only

## C. The rendering findings still open from the 2026-09-06 review

- **Wide characters (CONFIRMED HIGH).** `width()` counts UTF-16 units: a CJK title measures 78 and
  occupies 113 cells, wraps, and eats the hint line. Fix in the one `width()` everything routes
  through — East Asian W/F ranges inline (~25 lines, keeps zero-dep), treating *ambiguous* as narrow
  to match Windows Terminal, and say so where the limit is.
- Table can overshoot `columns` by up to +15 (an 8-column floor wins on narrow screens).
- `wide = Math.max(60, columns)` renders 60 columns into a 40-column terminal.
- Whole line classes never clipped: title/endpoint, terminals, empty-state, **the hint line**, unknown
  block, traffic.
- `pane.attached` still has no reader — with a pane open, its header is identical attached or not.
- Polish: `#` column blank past row 9, `1 process(es)`, a phantom empty column with no keyboard,
  trailing whitespace.

## D. Agent removal loses its own stop control

`unregister_agent` writes a stop control, commits, then deletes the agent — and `terminal_controls`
has `ON DELETE CASCADE` from `terminal_sessions`, so **the delete wipes the control it just wrote**.
The code's comment admits the design depends on winning that race. Observed losing three times on
2026-09-07: aify-env streamed into 404s for ten minutes until its own guard stopped the workers.

Fix: tombstone only after the stop is confirmed claimed, rather than betting on the window. This
changes deletion ordering on live agent rows — **operator sign-off before touching it**.

## F. HTTPS — an operator action, not a code fix

The certificate is correct for the address (`SAN: IP 192.168.100.10`); the only failure is

# v0.6.4 — the herdr surface

Design: [2026-09-07-herdr-as-the-pane-surface.md](2026-09-07-herdr-as-the-pane-surface.md). Three
revisions from the operator, 2026-09-07:

## The locked pane runs `aify-env`, not `aify-env tui`

*"one pane locked open all the time (cannot kill, locked) and that is aify-env not aify-env tui.
using tui version would be duplicate."* — correct: with the daemon running in that pane there is one
process and one view, where `tui` beside a daemon elsewhere is two renders of one truth.

**The trade to state plainly.** herdr's server becomes the daemon's parent, so a herdr server death
takes the fleet. That failure mode does not exist today. Against it: today the daemon dies when its
terminal closes, and a herdr pane survives detach — so for the ordinary case it is *better*, and only
the rare case is worse. Conditions: the pane is refused on accidental close, the daemon is
restartable from inside herdr, and **`aify-env` started any other way behaves identically** — herdr
must never become required.

## herdr's sidebar IS the picker

Its sidebar lists agents with status and opens a pane on click. That is the selection surface, and it
means aify-env does not need to grow one. `pane.report_agent` puts OUR agent ids and states there, so
the fleet appears in herdr's own vocabulary.

## Performance is a first-class requirement

*"my main pc is 16 core beast with 96gb ... but my laptop and other people have 8 cores and 32-64 gb
... so performance has to be good."*

**Measured on this host, 2026-09-07:**

| | RSS |
|---|---|
| aify-env daemon, 3 agents | 164 MB |
| one claude agent | ~141 MB |
| one idle Node process (an attach client's floor) | 48 MB |

At the 21-agent fleet this project documents, the agents alone are **~3 GB**. A pane per agent adds
**~1 GB — a third of the fleet's cost, purely to look at it**, plus 21 SSE streams. On a 32 GB laptop
that is not affordable.

On-demand with two or three panes open: **+96–144 MB, about 3%.** That is the budget.

**Budget rules for v0.6.4:**
- Panes open on demand. Never one per agent. (`blocked`-driven auto-open stays opt-in and later.)
- One socket to herdr for the whole daemon, not one per agent.
- The reconciler is event-driven with a SLOW backstop sweep. No per-agent polling.
- **Measure before and after on an 8-core box**, not this one. A budget proven on a 96 GB machine is
  not a budget.

## Where each surface earns its place

The operator's framing, and it is the right one — same base, three usage styles, each with a cost:

| surface | good for | cost |
|---|---|---|
| aify-comms dashboard | remote, any device, the whole fleet, chat and history | a browser, a service |
| `aify-env` / `tui` | local status at a glance: what is running, producing, healthy | one process |
| `aify-env herdr` | local productivity: real terminals, splits, keyboard | herdr + a pane per agent you open |

None replaces another. v0.6.4 adds the third without touching the first two.
