**Not changed, with the reason:**

- **B3:** the completion PATCH is already retried: `httpCall` retries PATCH three times with backoff on
  transient errors and 5xx (`aify-service-endpoint.mjs`, `isRetriableRequest`). The failure branch's
  own loop is a second layer. The report's "the success branch has no retry" was read without it.
- **T03:** the redeploy test's `;` PATH separator is right on Windows (Git Bash converts an inherited
  Windows PATH; `os.pathsep` is `:` on Linux), and a stub that was not found could never pass (the
  record file would not exist). e02f9464 makes that failure say so.
- **T03's stamp half:** under a failing git the doctor already refuses to certify (the sha is `unknown`,
  or `GIT_SHA` is reported as an override), so `dirty: false` there certifies nothing. KNOWN_ISSUES
  says so.
- **S7:** the missed case (an old-shape database) is covered by 424c58d0's boot test and gate.
- **writeDaemonPid (D4):** already documented as a test seam.

**Backlog, added by this pass:**

- **B8:** a 404 from a pre-0.7 service on `/bridges` reads "the service did not answer". Testing the
  wording needs `doctor.js` run as a child, which reaches aify-env on 8802, the live tier on this host.
- **B6 in full:** move each orphaned paragraph in `hermes-managed-host.js` to the constant it describes.
- **The hermes loop-ready marker (D4):** written and cleared, read by nothing since 0.7.0. Removing it
  touches the delivery loop, its module and several path-containment tests.
