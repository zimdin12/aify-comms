slices and getting it wrong is a ten-commit mistake rather than a one-commit one.

## The finding: slice 1 is not one slice

Eight of the nine move with a total dependency surface of **two trivial helpers**. The ninth,
`_refresh_expired_agent_live_states`, calls `_refresh_agent_live_state` — the status-computation
core. Moving it drags that core along, which is not slice 1, is not small, and is exactly the
"slice too big to review as a move" the reviewer's bound exists to prevent.

**So slice 1 becomes 1a and 1b.** 1a is the cache + the two bridge reconcilers: 133 lines, zero
cycles, and it still proves the import-identity gate on the real `_LIVE_STATE_CACHE`, which is the
whole reason slice 1 was chosen to go first. 1b is `_refresh_expired_agent_live_states`, deferred
until the status-core seam is mapped — possibly to its own slice near the end.

## The decision that shapes every slice — `_now` and `_load_settings`

Both live in `api_v2.py`, and a moved reconciler needs them. Three options, and this must be settled
once rather than per-slice:

1. **Import them from `api_v2` in the new module.** Simplest to write, and a CIRCULAR IMPORT: the
   router imports the reconcilers and the reconcilers import the router. Rejected.
2. **Move `_now` to a shared module and pass `settings` as a parameter.** Clean, no cycle, but it
   changes signatures — so a "pure move" commit also changes call sites, and the empty-behaviour
   claim gets harder to review, not easier.
3. **Move `_now` to a shared module; keep `_load_settings` reachable by passing the already-loaded
   settings dict, which most callers already have.** The sweep in `main.py` loads settings once per
   pass already (`_reconcile_settings`), so this is closer to how the code is used than the current
   per-function reload.

`_now` is a two-line UTC formatter with no dependencies; moving it to a shared module is
uncontroversial and unblocks everything. `_load_settings` is the real question, and it is a
behaviour-adjacent one: each reconciler currently reloads settings independently, so passing one
dict changes *when* settings are read even if it never changes *what* they say.

**Not decided unilaterally — this is in review.** A wrong answer here is repeated ten times.
