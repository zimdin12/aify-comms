Quick start

Install a client, then run a bridge.

bash install.sh --client claude \
  http://192.168.100.10:8800 --with-hook

Managed (the normal team workflow — one bridge per host/runtime):

cd /path/to/workspace-parent
aify-comms              # aify-comms.cmd on native Windows

Resident (a terminal you drive directly):

claude-aify --aify-agent manager --aify-role manager

Status legend

The six agent states (same dots used across Chat, Sessions, and Analytics).

  • working — live session, in an active turn right now.
  • online — live session, idle between turns.
  • available — no live session, but auto-starts on the next send.
  • blocked — in a turn but waiting on input/approval.
  • offline — no live session and not auto-startable.
  • stopped — explicitly disabled / hard-blocked.

Managed agents are run by a bridge (auto-start/stop, visible console). Resident agents are a terminal you drive directly.

Daily use

  • Send vs Queue — a normal send delivers now (waking/auto-starting the target); "Queue if busy" defers it until the agent finishes its current turn.
  • Expects reply — opens a tracked request (a contract). Open/overdue contracts surface on the Work page.
  • Console vs Messenger — Console is the agent's live terminal; Messenger is the chat thread. Toggle per conversation.
  • Compact vs Continue — Compact hands off into a fresh backing under the same agent ID; Continue-as starts a new agent from the current context.
  • Stopping — Stop ends a managed session; the agent stays available and re-starts on the next send unless set to offline/stopped.

Endpoint reference

Base /api/v1 unless noted. Spot-checked against the FastAPI router. Mostly for debugging integrations and tests — daily work happens in Chat, Sessions, Work Loop, and Environments.

Chat & channels

  • GET /messages/recent recent messages across the fleet
  • GET /messages/inbox/{agent} one identity's inbox (supports mode=headers)
  • POST /messages/send send a message; returns recipient status
  • DELETE /messages/{id} unsend a message
  • GET/POST /channels list / create channels
  • POST /channels/{name}/join|leave|read|send membership + post

Agents & sessions

  • GET /agents · GET /agents/{id} identity records
  • POST /agents/{id}/control stop, resume, or interrupt active work
  • PATCH /agents/{id}/session-mode flip resident ⇄ managed
  • GET /sessions · DELETE /sessions/{id} runtime session records
  • GET /environments connected execution environments

Work loop & runs

  • GET /contracts computed reply obligations over messages/runs
  • GET /dispatch/runs delivery/run audit records
  • GET /dispatch/runs/{id}/events per-run event stream
  • GET /analytics · /analytics/agent/{id} global / per-agent stats

Files & service

  • GET/POST /shared shared files (text + binary upload)
  • DELETE /shared/{name} remove a shared artifact
  • GET/PUT /settings read / merge settings
  • GET /health · /version health + build SHA / behind-count (origin root)

Agent-facing MCP tools (comms_send, comms_register, comms_spawn, comms_channel_*, comms_share, …) are documented in the README and the aify-comms skill — not duplicated here.
