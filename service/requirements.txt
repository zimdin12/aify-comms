# Core framework

# BOUNDED BELOW at 0.138.0 because the route gates need it. From 0.137.0 `include_router` stops
# flattening child routes into `app.routes` and leaves a lazy `_IncludedRouter` there, so a plain walk
# finds 11 entries where the app serves 129 and every route gate passes on nothing. 0.138.0 added
# `fastapi.routing.iter_route_contexts`, which yields the full inventory; the gates all walk it through
# `service/tests/served_routes.py`, and `test_the_route_inventory_is_not_empty.py` goes red if that
# walk ever collapses again. 0.137.x has neither the flat walk nor the helper.
#
# BOUNDED ABOVE at the version the service runs (0.139.2, read from the running container on 2026-09-23), for
# the same reason `mcp` is below: the next minor is a change nobody has looked at yet. A ceiling of
# `<0.137` was considered and rejected, because the next rebuild would have DOWNGRADED the running
# service to a version it has never served on.
fastapi>=0.138.0,<0.140
uvicorn[standard]>=0.32.0
pydantic>=2.0.0

# MCP server (SSE transport)
# Bounded ABOVE on purpose. `>=1.3.0` let pip take 2.0.0, which removed mcp.server.fastmcp entirely
# -- the API mcp/sse_server.py imports -- so the transport silently stopped mounting and startup logged
# only an INFO line. A lower bound with no ceiling is not a pin, it is a promise to accept whatever
# upstream does next. Porting to the 2.x API is its own piece of work; until then this targets 1.x and
# says so.
mcp[cli]>=1.3.0,<2
